# 复杂选择控件的通用处理

本轮以字段与候选列表的显式关系为依据，区分查询文字和已选择值。没有站点名、学校/地址字典、日期选择器品牌或业务接口分支。

## 合同

1. 观察 `combobox`、`aria-autocomplete`、`aria-controls`、列表归属、展开/禁用/加载/验证状态。关系只在元素所在 document/shadow root 内解析；重复 ID 或缺失目标为未知。
2. 向选择控件输入后进入 `pending_selection`。自动批次不反复覆盖查询，也不自动按 Enter 提交搜索。其他列表的同名选项不能用来完成它。
3. 候选相对输入前变化，或观察到 `aria-busy` 从加载转为完成后，才认为该轮候选可供选择。桥接器最多额外观察三秒，不消耗 Jev 请求；超时不是“无结果”，也不代表已选中。
4. 唯一、同名、归属明确且非加载中的选项可以自动点击；否则仍由 Jev 根据候选上下文判断；选择时同时检查操作和目标的置信度，任一低于 0.6 则交给调用方，不能只因 CLICK 操作置信度高就选一个含糊候选。这个门槛是路由策略，不是正确率声明。点击前守卫包括列表归属、查询值和加载状态，避免执行期间查询已经改变。
5. 点击后进入待确认状态，延迟回填或 Apply 后仍会继续检查。原控件的值相对点击前发生变化并显示选项值、原候选层关闭且没有验证错误时记录选择生效；若原控件被隐藏或变透明而未出现在交互快照中，还可使用点击前记录的字段显示证据：唯一列表归属、显式label限定的独占字段范围、范围内新增且精确匹配候选的可见文字/标题/可访问标签、列表关闭且无验证错误。范围外文字、点击前已有的文字和多字段容器不能确认。高亮、`aria-selected`、文字已填或选项消失单独都不是确认依据。这是 UI 证据，不等同于服务器保存成功。
6. 级联选择导致已确认控件值变化或验证失败时，撤销旧的已应用记录，允许重新填写。仍有未确认选择时不接受 DONE。

原生 select 保持直接选择及值检查。日期保留现有完整日期/月份上下文、禁用状态、翻月及 Apply 操作；不按某个网站的 DOM 写日历脚本。

## 验证和边界

`tests/agent-selection.test.mjs` 检查错误列表、查询/选择区分、旧建议、加载、高亮误判、提交确认、级联重置、歧义关系等负例。`tests/e2e/task-selection.mjs` 用真实扩展和隔离 Chromium，对普通 DOM 的独立弹层以及 shadow DOM 和自定义国家下拉三种结构执行国家、延迟学校建议、地址建议、跨月日期与 Apply。判分记录由测试服务独立保存，不提供给模型侧。

端到端脚本使用模拟 Jev，只证明通用观察与执行流程，不能证明模型在真实站点上的选择正确率。初轮机械验证没有付费调用；后续真实模型验收及失败记录见下文。跨网站验收仍是交付前待办。

当前选择确认针对单选弹层。无显式关联、自由文本允许不点选、保持展开的多选、返回值与候选标签不同且没有明确选中展示等情况可能保持未确认，需要调用方介入；不能靠文字相似或全页猜测降低确认标准。页面没有 loading 标记且旧结果在输入后才到达时，单靠 DOM 不能可靠知道该响应属于哪个查询，仍需真实场景验证。虚拟列表和滚动容器覆盖不在本轮通过声明中。

协议版本升为 7（上一真实站候选使用 6），bridge 和扩展需从同一候选构建。


## 正式网站失败后的修复进度

2026-09-26 的冻结候选 `84857b8` 已完成六例真实 Jev 实测，33 次请求，零自主端到端成功。独立报告保存在仓库 `.csquad/recovery/2026-09-26/selection-live/results/report.md`。学校/国家的页面选择成功但确认失败；日期无成功案例；地址建议流程未完整通过。上述机械测试不能替代这份失败结果。

宿主已移除输入后自动 Enter，以及把 DONE 替换为候选 Search 点击的两条捷径。搜索、提交、翻页需要单独的操作决策；模型指令明确用户的停止位置优先于填写后推进的默认习惯。此修改尚未证明模型会始终遵守停止位置，字段内新增标签的机械确认已增加，但旗帜/区号等缺少明确语义的显示仍未解决，正式网站确认仍待复验；修复中的代码不能作为已通过验收的候选。


补充零付费 DOM 诊断确认：真实学校控件选中后原输入节点仍连接、opacity 为 0，独占的 label 容器出现完整学校名；国家控件只显示旗帜与共享区号，隐藏兄弟控件内的国家名称不属于可用证据。实现不解析 CSS 国家码，不把隐藏标题或共享区号当作已选择国家。此类无明确显示语义的控件仍会保持未确认，不能宣称国家场景已经修复。


独立审查后的补充约束：输入查询原文加菜单闭合不能证明选中；失效的选择保留为未满足义务并允许重绑，不能由 DONE 绕过。每轮观察重验 owner 所属容器、label 与 ID 的唯一性、aria-controls 和列表节点身份，失去关联后永久撤销旧 witness；当前方案不推断被移除或替换的输入节点身份。可见性检查跨越 Shadow host 和 slot，隐藏宿主中的文字不能确认。对应 `tests/e2e/selection-witness.mjs` 为真实隔离扩展正负例，仍不是模型泛化验收。


## 受控 grid 与执行诊断（协议 6，未完成正式站验收）

独立正式站复测 `cb2777f` 的六例中，学校与 Expedia 日期当前 UI 自主通过；Country、Google、Bing、Booking 仍失败或未确认（报告 `selection-live-r2/results/report.md`）。26 新增请求，无重试；不能以此宣称跨网站可靠。

观察与执行现在共享显式受控 popup 的候选合同：唯一 owner 与唯一 popup ID；listbox 中的 option，或 grid 内仅包含一个 row/一个 gridcell 的包装条目。保留可访问主次文本，去除 aria-hidden 装饰；多行、多格、嵌套 popup、带其他操作控件、重复 owner 或隐藏条目不按候选处理。仍保留原始 DOM role，不把全页 generic 元素改成 option。此合同不覆盖通用数据表格或任意菜单。

点选后有独立三秒观察额度；跨文档的未确认点选仍保留义务。当前只接受既有独立字段显示/值变化证据，URL 变化、匹配的页面标题、候选消失都不是提交证明。缺少关联结果语义的地图地点页仍可能未确认，本轮不宣称已解决地图导航结果验收。

确认保护通道会有界等待 ready，重复 isolated 注入复用原通道；未收到策略应答仍拒绝点击，不自动重放。拒绝 trace 区分 ready_timeout、ack_timeout、channel_error，携实例与文档标识，不包含页面输入。MAIN 丢失首次握手或端口故障仍可能阻断；不以重新接收不可信页面 port 绕过保护，也不能把这些诊断改进称为 Booking 现场已修复。


受控 popup 的不合格成员保留拒绝标记，不能因未得到候选身份而退回普通 CLICK。观察、路由与执行共同检查该标记；已观察节点丢失 popup 关联后也保持拒绝。包装条目会聚合内部 row/gridcell 的禁用状态，并纳入点击前 guard。普通日历 grid 内、没有选择字段归属的原生按钮保留原有操作方式。相关负例直接尝试执行并检查零副作用，覆盖错误 owner/popup、多行多格、任意后代、加载、初始禁用、观察后禁用及关联失效后的再次观察。


普通原生按钮例外只适用于完整 composed 祖先链中没有选择弹层、没有嵌套 popup 的独立 grid。祖先遍历跨 Shadow host/slot；选择弹层根节点一经识别即保留身份，因此移除 role 后新增、此前未记录的后代也不能绕过拒绝。该历史仅属于当前文档实际节点，不推断全新替换节点的身份。


## 正式站结构补证后的通用修复（协议 7，尚待验收）

`8207ad8` 的 T120 四例正式站复测仍有零自主端到端成功；学校只在一次人工展开后成功，Booking/Google/UPS未完成。新增21请求，账本9580/10000。后续T151仅零付费结构补证，未点日期或地址候选，不是修复成功证明。

- 独立、非选择弹层的 grid 支持原生操作元素和显式 ARIA checkbox/radio/switch，包含 table/tbody/tr/td/span 的日历结构；读取 aria-checked。仍检查完整 composed 祖先和历史 popup 根，嵌套、禁用或曾有选择归属的控件不能借日历例外绕过。此规则允许表格中的明确控件，不把任意 gridcell 或日期字符串升级为可点击目标。
- 唯一受控 grid 的单 row/单 cell 条目允许从 popup 子节点到该 row 之间的包装层作为同一条目。图标/文本后代、多行多格及内部其他操作仍不合格。包含整个选择弹层的聚合祖先被单独拒绝，跨 shadow/slot；唯一显式拥有该弹层的控件仍可开关。
- 活动 ARIA 模态框检查自身与 composed 祖先的隐藏/透明/inert状态。原生 showModal 的浏览器屏障仍有效，即使CSS透明；普通 show() 不自动当成模态屏障。嵌套活动模态框会阻止外层控件操作。不能仅因弹窗在视口外就忽略它。
- 请求保留 modalBlocked、阻断弹窗ref/名称、基础资格排除计数和具体候选拒绝原因。没有可绑定字段可能是被过滤，不能自动解释为字段在下一页；普通命中测试与执行前守卫仍保留。

UPS 的 label for 与真实 input id 不匹配是独立问题；本轮不靠站点ID截断或猜label解决。学校无显式开关关系时的低置信handoff保持。Google结果页仍需要独立关联的选中语义，URL/标题不会自动确认；Country旗帜、多选及虚拟列表等限制保持。协议7的隔离测试不能覆盖或替代协议6的正式站失败，也不保证本轮现场通过。

协议7后续审查补充：聚合后代检查必须发生在所有独立grid例外之前，gridcell中含输入框不能为它包含的整个建议弹层提供点击豁免。多原生模态框按浏览器命中结果识别有效屏障，穿透shadow读实际命中，不按DOM次序或焦点猜层级；无法命中、结果矛盾或原生dialog本身DOM嵌套导致层级歧义时保持阻断，不宣称支持这类排序。上层原生modal之外的ARIA弹窗不再与它相互阻断，内部ARIA子模态仍有效。原生modal可以越过祖先inert，但自身及内部显式inert仍拒绝。执行前继续重验模态对象/集合和命中；关闭或新开窗口使旧guard失效。规范依据：[HTML modal与inert子树](https://html.spec.whatwg.org/multipage/interaction.html#modal-dialogs-and-inert-subtrees)。

## 精确点选后的确认阶段

候选点击已发出后，确认事务保留原valueId与完整候选语义。在独立生效证据出现前，不允许普通字段点击、填值、Enter、再次点选或页面/标签导航。任务只做原有3秒预算内的只读重观察；到期返回 `selection_unconfirmed`，并带回待确认候选及 `independent_selection_commit` 缺失证据，不继续询问模型或把等待超时当作成功。该限制不增加外部结果卡确认能力。

T182在协议7/7666ca5真实Chrome中，Booking本次10月20–23日可见日期表单自主成功；Maps精确建议已点选且人工可见完整地址，但自动确认未完成；UPS指定完整地址被页面自定义长度校验拒绝（原生maxlength未声明）。三例13请求、无代点/提交。不能擅自截断输入或把短查询视为原完整实体已选择，不能以任意页面同地址或URL变化确认地图结果。字段关联错误与外部结果实体关联仍需独立证据支持。

确认期间即使用完模型请求或动作步骤预算，已发出的点选仍可在原窗口内做只读观察；不增加请求/动作、不越过未授权origin，也不绕过总超时/abort。窗口结束仍返回真实预算停止原因，附带待确认义务；若已观察到生效，则返回 `committedSelections` 中仍有效的选择事实，不据此擅自宣布整个任务done。所有终止路径统一保留现有pending信息，失效的历史选择不列入committed。
