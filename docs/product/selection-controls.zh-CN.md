# 复杂选择控件的通用处理

本轮以字段与候选列表的显式关系为依据，区分查询文字和已选择值。没有站点名、学校/地址字典、日期选择器品牌或业务接口分支。

## 合同

1. 观察 `combobox`、`aria-autocomplete`、`aria-controls`、列表归属、展开/禁用/加载/验证状态。关系只在元素所在 document/shadow root 内解析；重复 ID 或缺失目标为未知。
2. 向选择控件输入后进入 `pending_selection`。自动批次不反复覆盖查询，也不自动按 Enter 提交搜索。其他列表的同名选项不能用来完成它。
3. 候选相对输入前变化，或观察到 `aria-busy` 从加载转为完成后，才认为该轮候选可供选择。桥接器最多额外观察三秒，不消耗 Jev 请求；超时不是“无结果”，也不代表已选中。
4. 唯一、同名、归属明确且非加载中的选项可以自动点击；否则仍由 Jev 根据候选上下文判断；选择时同时检查操作和目标的置信度，任一低于 0.6 则交给调用方，不能只因 CLICK 操作置信度高就选一个含糊候选。这个门槛是路由策略，不是正确率声明。点击前守卫包括列表归属、查询值和加载状态，避免执行期间查询已经改变。
5. 点击后进入待确认状态，延迟回填或 Apply 后仍会继续检查。需要原控件仍存在、显示选项值、候选层关闭且没有验证错误，才记录选择生效。高亮、`aria-selected`、文字已填或选项消失单独都不是确认依据。这是 UI 证据，不等同于服务器保存成功。
6. 级联选择导致已确认控件值变化或验证失败时，撤销旧的已应用记录，允许重新填写。仍有未确认选择时不接受 DONE。

原生 select 保持直接选择及值检查。日期保留现有完整日期/月份上下文、禁用状态、翻月及 Apply 操作；不按某个网站的 DOM 写日历脚本。

## 验证和边界

`tests/agent-selection.test.mjs` 检查错误列表、查询/选择区分、旧建议、加载、高亮误判、提交确认、级联重置、歧义关系等负例。`tests/e2e/task-selection.mjs` 用真实扩展和隔离 Chromium，对普通 DOM 的独立弹层以及 shadow DOM 和自定义国家下拉三种结构执行国家、延迟学校建议、地址建议、跨月日期与 Apply。判分记录由测试服务独立保存，不提供给模型侧。

端到端脚本使用模拟 Jev，只证明通用观察与执行流程，不能证明模型在真实站点上的选择正确率。本轮不运行付费调用。真实模型跨网站验收仍是交付前待办。

当前选择确认针对单选弹层。无显式关联、自由文本允许不点选、保持展开的多选、返回值与候选标签不同且没有明确选中展示等情况可能保持未确认，需要调用方介入；不能靠文字相似或全页猜测降低确认标准。页面没有 loading 标记且旧结果在输入后才到达时，单靠 DOM 不能可靠知道该响应属于哪个查询，仍需真实场景验证。虚拟列表和滚动容器覆盖不在本轮通过声明中。

协议版本升为 4（旧 P2a 分支使用 3），bridge 和扩展需从同一候选构建。


## 正式网站失败后的修复进度

2026-09-26 的冻结候选 `84857b8` 已完成六例真实 Jev 实测，33 次请求，零自主端到端成功。独立报告保存在仓库 `.csquad/recovery/2026-09-26/selection-live/results/report.md`。学校/国家的页面选择成功但确认失败；日期无成功案例；地址建议流程未完整通过。上述机械测试不能替代这份失败结果。

宿主已移除输入后自动 Enter，以及把 DONE 替换为候选 Search 点击的两条捷径。搜索、提交、翻页需要单独的操作决策；模型指令明确用户的停止位置优先于填写后推进的默认习惯。此修改尚未证明模型会始终遵守停止位置，也未解决控件替换为标签或旗帜后的选择确认；修复中的代码不能作为已通过验收的候选。
